# example — サンプル機械

このアプリの「読込」ボタンで開ける機械(DFA / DTM)のサンプルです。表示名は
ファイル名(拡張子を除く)から付きます。読み込んだら「再生」で実行できます。
拡張子は種別で分かれます: **DFA=`.tmvdfa` / DTM=`.tmvdtm`**(tmv = Turing Machine Visualizer)。

## 保存フォーマット(コンパクトなテキスト)
保存/読込は 1 行のパイプ区切りテキストです(JSON より小さく、DFA なら ACCDFA が
そのまま解析できるほど素直):
```
<k>|<states>|<alphabet>|<start>|<accepts>|<word>|<transitions>
```
- `k`: `d`(DFA)/`t`(DTM)。`states`/`alphabet`/`accepts` は `,` 区切り。
- `transitions`: `;` 区切り。DFA=`from,read,to` / DTM=`from,read,to,write,move`
  (`read`/`write` の空フィールド=空白 null、`move`=`L`/`R`)。
- 状態名・記号に区切り文字(`| , ; \`)が含まれる場合は `\` でエスケープ。
- 読込は後方互換として、先頭が `{` の旧 JSON 形式も受け付けます。

## dfa-divisible-by-3.tmvdfa — DFA(正則言語の例)
2進数(MSB 先頭)が **3 の倍数**かを判定する DFA。状態 `r0/r1/r2` が「これまで
読んだ値 mod 3」を表し、ビット `d` を読むごとに `r ← (2r + d) mod 3`。受理は `r0`。
- サンプル入力: `110`(=6 → 3 の倍数 → **受理**)。`10`(=2)なら拒否。

## dfa-even-a-tri-b.tmvdfa — DFA(積構成の例)
`{a, b}` 上で「**a が偶数個 かつ b が 3 の倍数個**」を判定する DFA。2つの単純な条件
(a の偶奇=2状態、b の個数 mod 3=3状態)の**直積**で 6 状態を作る、複雑な DFA の例。
状態は `0`–`5`(= a偶奇×3 + b剰余)、受理は `0`(偶数個 a・b≡0)。
- サンプル入力: `aabbb`(a×2・b×3 → **受理**)。`ab` なら拒否。
- 状態が数字・記号が `a`/`b` なので、`accdfa.tmvdtm` にも流せます。

## dtm-palindrome.tmvdtm — DTM(DFA にはできない例)
`{a, b}` 上の **回文(palindrome)** を判定する 1 テープ DTM。左端の未照合を `x`、
右端の未照合を `y` でマークし、両端を突き合わせながら内側へ縮めます。回文言語は
**非正則**なので DFA では判定できず、テープ(記憶)を持つ TM ならではの例です。
- サンプル入力: `abba`(**受理**)。`ab` なら拒否。「再生」で最後まで走らせてください。
- 実装メモ: このエンジンのテープは左端が境界なので、記号を消さずマーカで進め、左端を
  越えて左移動しない設計にしています。

## dtm-subset-sum.tmvdtm — DTM(NP完全を指数時間で総当たり)
**部分和問題**(数の集合から、合計が目標になる部分集合があるか)を、DTM が
**全 2^k 通りの部分集合を試して**判定する例。NP完全問題を決定的機械で解くと
**指数時間**になる、を目で見られる(17状態と小さいが、実行ステップは 2^k で増える)。
- 入力(単項): `n<数>,n<数>,…,n<数>#<目標>`。各数は `1` の並び、前の `n`/`y` が
  選択ビット(全 `n`=空集合から開始)、`#` の後が目標(単項)。
- 動作: 選択ビットを2進カウンタとして全部分集合を列挙し、選んだ数の `1` を目標と相殺して
  合計=目標を判定。一致で受理、全滅で拒否。
- サンプル入力: `n11,n111,n1#1111`(={2,3,1}・目標 4 → 部分集合 {3,1}=4 → **受理**)。
  `n11,n111#111111`(={2,3}・目標 6 → 最大 5 なので → 拒否)。
- 目安: 数が k 個で約 2^k 回の試行。k を増やすとステップが急増(k=7 で ~2.4万ステップ)する
  ので、「再生(高 Hz)」でどうぞ。数は小さめ・少なめが快適。

## dtm-binary-adder.tmvdtm — DTM(論理回路: 2進加算器)
2進数の足し算 `x+y` を計算する DTM。**下位ビットから桁上げを伝える**(=リップルキャリー
加算器と同じ)。入力は MSB 先頭 `x+y`、結果は `=` の右に **LSB 先頭**で書き出す。
TM が(判定でなく)**関数を計算**する例で、論理回路の加算器に対応する。
- サンプル入力: `101+11`(=5+3)。実行後テープは `…=0001`(= の右が LSB 先頭 → `1000`b = **8**)。
- x の MSB(左端)は番兵にして左端境界を越えない設計。「再生」で桁上げが伝播する様子が見える。

## accdfa.tmvdtm — DTM(DFA を実行する ACCDFA)
**アプリで保存した DFA の `.tmvdfa` をそのままテープに載せると、DTM がそれを解析して DFA を
入力語に対して実行**し、受理/拒否します(変換ツール不要)。判定言語は
A_DFA = { ⟨D, w⟩ | DFA D が w を受理 }。170 状態 / 5355 遷移。

### 前提
- **状態は 10 進の数字列**(`0,1,2,…` と**桁数任意=状態数は無制限**)
- **入力記号は `a`–`e`**(最大 5 種)
- 現在状態は右端のレジスタに置き、可変長の状態名を比較・コピーして DFA を1ステップずつ実行する。

### 使い方
1. アプリで DFA を作る。**状態名を `0`,`1`,`2`,…**(何桁でも可)にし、記号は `a`–`e`。
2. その DFA の入力欄に判定したい語(例 `aab`)を入れて「保存」→ `.tmvdfa` が得られる。
3. `accdfa.tmvdtm` を「読込」→ 選択。
4. 保存した DFA の **`.tmvdfa` の中身を、そのまま入力(テープ)欄に貼る** → 「再生」。
   判定対象の語は、その中身の `word` フィールド(6番目。例 `d|…|…|…|…|aab|…` の `aab`)。

同梱のサンプル入力は「a が偶数個」の DFA(状態 `0`/`1`)を `aa` で判定するもので、
`d|0,1|a,b|0|0|aa|0,a,1;0,b,0;1,a,0;1,b,1` → **受理**。

> 補足: DFA を1文字ずつ解析し、入力記号ごとに遷移表を線形走査するため、総ステップ数は
> やや多めです。「進む」連打より「再生(速度 4x)」が快適です。

### dfa_to_accdfa.py — 任意の DFA を ACCDFA へ流せる形に正規化
状態名や記号が ACCDFA の規約(**数字状態・記号 a–e**)に合わない `.tmvdfa` でも、
このスクリプトで正規化できます(状態を `0,1,2,…` に採番、記号を `a`–`e` に対応付け):
```
python3 example/dfa_to_accdfa.py path/to/foo.tmvdfa [判定したい語]
```
標準出力の1行を `accdfa.tmvdtm` の入力(テープ)欄に貼って「再生」。状態・記号の
対応表は標準エラーに出ます。**入力記号が6種以上のときだけ**変換できず、その旨を表示します。

例: `dfa-divisible-by-3.tmvdfa`(状態 `r0/r1/r2`・記号 `0/1`)を語 `110` で変換すると
`d|0,1,2|a,b|0|0|bba|0,a,0;0,b,1;1,a,2;1,b,0;2,a,1;2,b,2` になり、ACCDFA に流すと受理。
